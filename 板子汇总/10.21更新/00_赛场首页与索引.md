- 本地编译：`g++ -std=c++17 -O2 -Wall -DLOCAL a.cpp -o a`；查越界加 `-D_GLIBCXX_DEBUG`（Linux 再加 `-fsanitize=address,undefined`）。
- 开了 `sync_with_stdio(false)` 后不要混用 `scanf/printf` 和 `cin/cout`；输出大量换行用 `'\n'`，别用 `endl`。
- 老模板里很多带 `#define int long long`：拼接时 `main` 要写成 `signed main`，`scanf("%d")` 会读错，`memset 0x3f` 得到的是 `0x3f3f3f3f3f3f3f3f`，判 INF 必须和它比。

### 2. 常见坑清单（WA / RE / TLE / MLE 前先过一遍）

| 现象 | 先查这些 |
|---|---|
| WA | 爆 int（乘法、求和、`1 << 40` 要写 `1LL << 40`）；取模后出现负数（`(x % m + m) % m`）；多组数据没清空（全局数组、vector、计数器、`visnum` 类时间戳）；下标 0/1-based 混用；`n = 1`、空集、全相同等边界；浮点比较没用 eps |
| RE | 数组开小 / 下标 -1；递归 DFS 在 1e5~1e6 深链爆栈（改迭代）；除以 0；`vector` 越界（`-D_GLIBCXX_DEBUG` 一跑就知道） |
| TLE | `endl` 刷新；`cin` 没关同步；`memset` 整个大数组放在多组数据循环里；SPFA 被卡（无负边就用 Dijkstra）；`map` / `unordered_map` 常数；递归里传值拷贝 vector |
| MLE | `#define int long long` 让数组翻倍；主席树 / 树套树节点池按最坏估算；`vector<vector<>>` 小行太多；SAM 的 `next[26]` 在 n=1e6 时约 220MB |

### 3. 数据范围 → 复杂度速估（1 秒约 1e8 次简单运算）

| n 的范围 | 能接受的复杂度 | 常见做法 |
|---|---|---|
| ≤ 10~12 | O(n!)、O(n·2^n·n) | 全排列、状压 DP |
| ≤ 20~25 | O(2^n)、O(2^{n/2}) | 状压、折半搜索 |
| ≤ 500 | O(n³) | Floyd、区间 DP、KM、高斯消元 |
| ≤ 5000 | O(n²) | 二维 DP、朴素 Prim / Dijkstra |
| ≤ 1e5~2e5 | O(n log² n)、O(n√n) | 线段树、树套树、莫队、点分治 |
| ≤ 1e6 | O(n log n)、O(n) | 排序、BIT、线性筛、KMP / Z 函数、SA |
| ≤ 1e9~1e18 | O(√n)、O(log n)、O(n^{2/3}) | 数论、矩阵快速幂、类欧、杜教筛、BM |

### 4. 对拍流程（模板见 DP杂项 › 对拍）

1. 写暴力 `bf.cpp`（越笨越好），写数据生成 `data.cpp`（小数据：n ≤ 10，值域 ≤ 10）。
2. 三个程序分别编译，运行 `test.cpp`；出现 WA 时 `data.in` 就是反例，手算或加输出定位。
3. 先拍小数据找正确性，再造最大数据测时间和内存。

### 5. 提交前检查

- [ ] 删掉调试输出（`dbg` 在非 LOCAL 下已经无效）；输出格式（空格、换行、大小写、Yes/YES）。
- [ ] 多组数据：所有全局状态清空了吗？清空的范围按本组 n，而不是 MAXN。
- [ ] 最大数据跑一遍：时间、内存、是否爆 int。
- [ ] 特殊情况：n = 1、无解、答案为 0、所有数相同、负数。
